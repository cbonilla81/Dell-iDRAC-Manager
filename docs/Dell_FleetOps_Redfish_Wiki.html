What is Redfish?

Redfish is an open, standards-based RESTful management API for servers, storage, and other data-center equipment, maintained by the Distributed Management Task Force (DMTF).

It uses HTTPS requests and JSON responses so administrators can automate hardware management without clicking through a controller's web interface. On Dell PowerEdge servers, the iDRAC management controller exposes Redfish resources.

Remember: Redfish is the API standard; iDRAC is Dell's hardware management controller implementing it. Redfish is not a separate application you need to install on your CentOS VM.

How Redfish works with Dell FleetOps

FleetOps uses the backend to authenticate to each iDRAC. The frontend should never communicate directly with controllers using stored credentials.

Hands-on Redfish examples

1. Check reachability and certificate trust

curl -Iv https://IDRAC-IP/redfish/v1/

2. Query the service root

curl --fail-with-body --user 'redfish-reader' \
  https://IDRAC-IP/redfish/v1/

curl will prompt for the password. This example assumes a trusted iDRAC certificate.

3. Discover systems

curl --fail-with-body --user 'redfish-reader' \
  https://IDRAC-IP/redfish/v1/Systems

4. Query one system

curl --fail-with-body --user 'redfish-reader' \
  https://IDRAC-IP/redfish/v1/Systems/System.Embedded.1

The final path is a common Dell example, not universal. Prefer the system URI returned in the previous response.

5. Inspect update capabilities (read-only)

curl --fail-with-body --user 'redfish-reader' \
  https://IDRAC-IP/redfish/v1/UpdateService
Lab-only TLS diagnostic: curl -k disables certificate verification. Use it only to isolate trust issues; configure valid certificates or an approved CA before production automation.

How FleetOps should use Redfish

1

Onboard. Add iDRAC IP or hostname and a least-privilege account. Confirm connectivity and certificate trust.

2

Discover. Read the service root, follow Systems/Chassis/Managers links, and capture model, Service Tag and component identifiers.

3

Inventory. Store a timestamped snapshot of installed hardware, firmware versions and health status.

4

Assess. Compare versions against verified Dell catalog entries and an administrator-approved baseline.

5

Approve. Require an authorized change, compatibility review, backup, maintenance window and rollback plan before updates.

6

Execute and verify. Use model-supported update actions, monitor tasks, re-inventory and record results.

Recommended first milestone: deliver reliable read-only discovery and inventory before implementing power control or firmware-changing operations.

Production safeguards

  • Use a dedicated management VLAN and restrict outbound FleetOps access to approved iDRAC endpoints on TCP 443.
  • Use per-role accounts and avoid using the default iDRAC administrator for inventory polling.
  • Validate TLS certificates; never use permanent -k or disabled certificate checks.
  • Encrypt credentials at rest, protect the application secret, and rotate credentials on schedule.
  • Keep firmware actions disabled by default; require human approval and a maintenance window.
  • Verify component compatibility, Dell release notes, platform dependencies and host workload readiness.
  • Use limited concurrency, pilot servers, immutable audit logs and post-update health checks.
  • Back up the FleetOps database and its encryption key separately and securely.
